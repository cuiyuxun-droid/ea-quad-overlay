# 四模态数据集二次开发技术路线解释（L4）

本文档用于解释“为什么采用现有数据集二次开发 + 代码批量提特征 + 少量人工精标”的技术路线。  
它和任务包文档配套使用：任务包文档负责“怎么做”，本文档负责“为什么这样做”。

## 1. 当前项目真正需要什么数据

项目当前开发到 L4。L4 的核心不是重新训练四个模态的底层模型，而是判断四个模态之间是否矛盾，以及在矛盾时如何调整融合权重。

因此，当前阶段最需要的数据不是“从零录很多视频”，而是：

1. 同一片段上的文本、语音、宏表情、微表情特征。
2. 四个模态在统一时间轴上的 VA 表示。
3. 模态之间是否矛盾的标签。
4. 矛盾类型标签。
5. 人工认可的融合权重。

也就是说，L4 数据的重点是“模态关系”，不是单个模态本身。

## 2. 为什么不直接完全自采

完全自采当然可以做，但不适合作为第一路线。

原因有四个：

1. 成本高  
   需要招募、录制、授权、切片、转录、标注、质检，周期很长。

2. 风险高  
   微表情很难稳定诱发，录了很多视频也可能没有足够有效样本。

3. 当前阶段不需要  
   项目才到 L4，核心是验证融合和路由逻辑，不需要立刻构建完整端到端大数据集。

4. 公开数据已经提供底座  
   CH-SIMS、MELD、IEMOCAP、MOSEI 等数据集已经有文本、语音、视频和情绪标签，适合做二次开发。

所以更合理的路线是：

```text
先用公开/已有多模态数据集做二次开发
再用少量自采补公开数据缺口
```

## 3. “自己开发”具体指什么

这里的“自己开发”不是简单下载数据，也不是全部自己录制，而是开发一个新的标注层和特征层。

具体包括：

1. 自己统一不同数据集的样本索引。
2. 自己编写代码批量提取四模态特征。
3. 自己补充原数据集没有的微表情候选特征。
4. 自己补充 L4 所需的矛盾类型标签。
5. 自己补充融合权重标签。
6. 自己生成适配项目仓库的数据 manifest。
7. 自己形成可复现的数据版本和实验报告。

这就是数据集二次开发。

## 4. 为什么分成 FeatureBank 和 L4-Gold

建议最终形成两个数据产物：

```text
EA-FeatureBank
EA-L4-Gold
```

### 4.1 EA-FeatureBank

`EA-FeatureBank` 是大规模特征库。

它主要靠代码生成：

- text embedding
- speech embedding
- macro 表情特征
- micro 候选特征
- 弱 VA 标签
- 样本质量指标

它的作用：

- 支撑 L2/L4 的大规模输入。
- 作为弱监督数据。
- 帮助筛选 L4 候选样本。
- 不要求每条都人工精标。

### 4.2 EA-L4-Gold

`EA-L4-Gold` 是人工精标集。

它主要靠人工确认：

- contradiction_type
- fusion_weights
- involved_modalities
- micro positive / negative
- reason

它的作用：

- 评估 L4 是否判断正确。
- 标定 L4 路由阈值。
- 比较等权融合、置信度加权、规则权重和当前 L4 router。
- 作为给老师展示的核心成果。

### 4.3 为什么不能只做一个数据集

如果全部人工精标，工作量太大。  
如果全部靠代码弱标签，L4 评估不可靠。

所以必须分层：

```text
大规模弱标签特征库 + 小规模高质量人工精标集
```

这是更符合当前团队能力和项目进度的方案。

## 5. 每个数据集在路线中的作用

### 5.1 CH-SIMS / CH-SIMS v2.0

CH-SIMS 是中文主底座。

它的价值：

- 中文文本、语音、视频三模态。
- 有情感标签。
- 和项目中文场景更接近。

它在路线中的作用：

- 优先批量提取四模态特征。
- 优先建立中文 FeatureBank。
- 优先抽样构建 L4-Gold。

需要补的内容：

- micro 候选特征。
- L4 矛盾类型。
- 融合权重。
- 统一 manifest。

### 5.2 MELD

MELD 适合补对话场景。

它的价值：

- utterance 级对话片段。
- 有文本、语音、视频。
- 有情绪和情感极性标签。

它在路线中的作用：

- 补充多人对话。
- 补充语气和文本不一致的样本。
- 补 `sarcasm` 和 `intensity_mismatch`。

需要补的内容：

- micro 候选。
- L4 contradiction_type。
- fusion_weights。

### 5.3 IEMOCAP

IEMOCAP 适合高质量情绪对话。

它的价值：

- 音视频质量高。
- 有文本转录。
- 有情绪标签和 valence / activation 等信息。

它在路线中的作用：

- 补充高质量英文情绪对话。
- 支撑 speech 和 macro 的可靠特征。
- 用于 L4 融合验证。

需要补的内容：

- micro 候选。
- L4 标签。
- 和仓库一致的 manifest。

### 5.4 CMU-MOSEI / MOSI

MOSEI/MOSI 适合做大规模三模态补充。

它的价值：

- 样本量大。
- 有文本、语音、视觉。
- 有 sentiment / emotion 标签。

它在路线中的作用：

- 扩充 FeatureBank。
- 支撑 text/speech/macro 分支。
- 从人脸清晰片段中筛一部分进入 L4-Gold。

需要注意：

- 不是所有视频都适合 micro。
- 人脸不清楚的样本可以保留 text/speech/macro，但不要强行做 micro。

### 5.5 MUStARD

MUStARD 适合专门补反讽。

它的价值：

- sarcasm 标签明确。
- 有多模态信息。

它在路线中的作用：

- 补 L4 的 `sarcasm` 类型。
- 帮助验证文本和语音/表情冲突时的权重策略。

### 5.6 少量自采

自采只作为补洞手段。

主要补：

- hidden_emotion
- masking
- 高质量正脸微表情

自采不作为前期主路线，因为成本高且不可控。

## 6. 代码提取和人工标注的边界

### 6.1 适合代码批量做的事

这些任务应该尽量自动化：

- 从数据集读取视频、音频、文本。
- 抽音频。
- 切片。
- 人脸检测。
- 文本特征提取。
- 语音特征提取。
- 宏表情特征提取。
- 微表情候选特征提取。
- 质量指标统计。
- 弱 VA 标签映射。
- manifest 生成。

### 6.2 必须人工确认的事

这些任务不能完全依赖代码：

- 是否真的存在微表情。
- 矛盾类型是什么。
- 哪些模态发生冲突。
- 融合权重是否合理。
- reason 是否说得通。

原因是 L4 处理的是“模态关系”和“语义冲突”，只靠自动规则容易误判。

## 7. 数据流解释

整个数据流如下：

```text
现有数据集
  -> source_index
  -> 代码批量提取特征
  -> EA-FeatureBank
  -> 自动筛选 L4 候选
  -> 人工精标
  -> EA-L4-Gold
  -> L4 baseline / router 评估
```

每一步的意义：

1. `source_index`  
   解决不同数据集格式不统一的问题。

2. 批量提取特征  
   把所有数据变成项目四模态输入格式。

3. `EA-FeatureBank`  
   提供大规模弱监督样本。

4. 自动筛选 L4 候选  
   减少人工标注工作量。

5. 人工精标  
   得到可靠的 L4 gold 标签。

6. L4 评估  
   判断动态路由和融合权重是否真的有效。

## 8. 为什么当前只服务 L4

项目目前开发到 L4，所以数据路线必须聚焦。

当前不应该主做：

- 人格问卷。
- L6 大五人格回归。
- L5 报告生成评价。
- 长期记忆数据。
- 大规模真实用户采集。

这些以后可以做，但现在会分散精力。

当前应该主做：

- 四模态特征对齐。
- 模态间 VA 差异。
- 矛盾类型。
- 融合权重。
- 路由策略评估。

## 9. 最终该如何对外表述

可以这样向老师解释：

> 我们的数据集开发不采用完全从零采集的方式，而是采用“现有多模态数据集二次开发”的路线。我们会先对 CH-SIMS、MELD、IEMOCAP、MOSEI、MUStARD 等数据集批量提取文本、语音、宏表情和微表情候选四模态特征，形成 EA-FeatureBank；再从中筛选代表性样本，人工补充 L4 所需的矛盾类型、融合权重和微表情正负确认，形成 EA-L4-Gold。这样既能利用公开数据的规模，又能形成我们项目独有的 L4 标注层。

## 10. 路线总结

一句话总结：

```text
公开数据提供规模，代码补齐四模态特征，人工补齐 L4 关系标签。
```

这条路线的优点：

- 比完全自采更快。
- 比直接用公开数据更贴合项目。
- 能形成项目自己的数据贡献。
- 能直接服务当前 L4 模块。
- 后续可以自然扩展到 L5/L6。
