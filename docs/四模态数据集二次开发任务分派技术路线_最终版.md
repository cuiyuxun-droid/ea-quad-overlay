# 四模态数据集二次开发任务分派技术路线

项目阶段：当前只服务 L4  
目标：基于现有多模态数据集，通过代码批量补齐四模态特征，并人工补充 L4 必需标签。  
团队人数：5 人  

## 1. 项目总目标

我们要开发的数据不是从零录制的大规模视频集，而是一个基于现有多模态数据集的二次开发数据集：

```text
CH-SIMS / MELD / IEMOCAP / MOSEI / MUStARD
  -> 批量提取 text / speech / macro / micro 特征
  -> 补充 L4 标签
  -> 生成仓库可直接读取的 manifest
  -> 用于 L4 矛盾检测和动态融合权重实验
```

最终数据集名称：

```text
EA-Quad-Overlay
```

最终需要形成两类数据：

| 数据 | 作用 | 来源 |
|---|---|---|
| `EA-FeatureBank` | 大规模四模态特征库，用于训练/预训练/弱监督 | 代码批量提取 |
| `EA-L4-Gold` | L4 精标集，用于矛盾检测和融合权重评估 | 人工标注 |

## 2. 要处理哪些数据集

### 2.1 CH-SIMS / CH-SIMS v2.0

用途：中文主数据集。

需要处理：

1. 批量读取原始视频、音频、文本。
2. 提取 text 特征。
3. 提取 speech 特征。
4. 提取 macro 表情特征。
5. 从视频中提取 micro 候选特征。
6. 把原始情感标签映射成 `VA_self` 和 `VA_inter`。
7. 选出一部分样本进入 L4 人工精标。

建议处理规模：

- 批量特征：尽量全量处理。
- L4 精标：先 200 条，后续扩到 300-500 条。

### 2.2 MELD

用途：对话、反讽、强度不一致。

需要处理：

1. 按 utterance 读取视频片段。
2. 提取 text、speech、macro、micro 候选特征。
3. 根据 emotion/sentiment 映射整体情绪。
4. 筛选 `sarcasm`、`intensity_mismatch` 候选。
5. 进入 L4 人工精标。

建议处理规模：

- 批量特征：筛选人脸清楚的样本批量处理。
- L4 精标：100-200 条。

### 2.3 IEMOCAP

用途：高质量英文情绪对话。

需要处理：

1. 读取音视频、转录文本、情绪标签。
2. 使用 valence / activation 映射 `VA_inter`。
3. 提取四模态特征。
4. 筛选模态矛盾明显的样本。
5. 进入 L4 人工精标。

建议处理规模：

- 数据可用后批量处理。
- L4 精标：100-200 条。

### 2.4 CMU-MOSEI / MOSI

用途：大规模三模态补充。

需要处理：

1. 批量提取 text、speech、macro。
2. 只对人脸清楚的视频提取 micro 候选。
3. 根据 sentiment/emotion 映射弱标签。
4. 筛选高质量样本进入 L4 精标。

建议处理规模：

- 批量特征：可用样本尽量处理。
- L4 精标：50-150 条。

### 2.5 MUStARD

用途：专门补 `sarcasm`。

需要处理：

1. 提取 text、speech、macro、micro 候选。
2. 保留人脸可见样本。
3. 人工标注 sarcasm 的融合权重。

建议处理规模：

- L4 精标：30-80 条。

### 2.6 少量自采

用途：补公开数据中不足的 `hidden_emotion` 和 `masking`。

需要处理：

1. 录制强装平静、隐藏真实情绪的片段。
2. 按同一流程提取四模态特征。
3. 人工补 L4 标签。

建议处理规模：

- 30-100 条。

## 成员 B：数据集整理与样本筛选

### 负责内容

B 负责把 CH-SIMS、MELD、IEMOCAP、MOSEI、MUStARD 的原始数据整理成统一索引。

### 具体任务

1. 整理 CH-SIMS 路径和元数据。
2. 整理 MELD 路径和元数据。
3. 整理 IEMOCAP 路径和元数据。
4. 整理 MOSEI/MOSI 路径和元数据。
5. 整理 MUStARD 路径和元数据。
6. 对每条样本记录：

```csv

```

7. 对每条样本打质量标签：

```csv
face_quality,audio_quality,text_quality,usable_for_micro,usable_for_l4
```

8. 筛掉低质量样本。
9. 给 C 和 D 提供待标注样本列表。

### B 的筛选标准

保留：

- 人脸清楚。
- 音频清楚。
- 文本完整。
- 片段长度合适。
- 情绪表达明显。
- 可能存在模态矛盾。

剔除：

- 人脸太小。
- 多人脸无法确定说话人。
- 镜头频繁切换。
- 音频噪声过大。
- 文本缺失。
- 时间戳不清楚。

## 成员 C：微表情候选检测与人工确认

### 负责内容

C 负责 micro 模态，不要求全量人工逐帧标，而是“代码生成候选 + 人工确认”。

### 具体任务

1. 配合 E 跑人脸检测。
2. 检查 micro 候选片段。
3. 对 L4 Gold 样本人工确认是否存在微表情。
4. 有微表情则标：

```text
onset_time
apex_time
offset_time
AU
intensity
confidence
```

5. 没有微表情则明确标 negative。
6. 记录 micro 候选检测失败案例。
7. 统计 micro positive / negative 数量。

### C 的标注格式

```json

  "ea_id": "EAQ000001",

  "has_micro_expression": true,

}
```

## 6. 统一注意事项

1. 当前只服务 L4，不做 L5/L6。

2. 大规模特征用代码批量提取，不靠人工一条条处理。

3. 人工只负责代码无法可靠判断的部分：
   - 微表情正负确认
   - 矛盾类型
   - 融合权重
   - reason

4. 优先使用 CH-SIMS 作为中文主底座。

5. MELD 和 MUStARD 主要补反讽。

6. IEMOCAP 和 MOSEI 主要补高质量三模态情绪样本。

7. 少量自采只用于补公开数据不够的 hidden_emotion 和 masking。

8. 不要重新发布公开数据集原始视频，只保存索引、特征和新增标注。

9. 所有样本必须有 `ea_id`，并能追溯 source_dataset 和 source_id。

10. `fusion_weights` 四项必须加起来等于 1。

11. `contradiction_type` 只能使用代码已有五类。

12. 低质量视频不要强行提 micro。

13. 每周必须有可验收产出，不要只做调研。

## 7. 给老师汇报的简短说法

我们将数据集开发拆成两条线：第一条线由代码批量处理 CH-SIMS、MELD、IEMOCAP、MOSEI、MUStARD，提取文本、语音、宏表情和微表情候选四模态特征，形成 `EA-FeatureBank`；第二条线由人工从中精标 300-500 条 L4 样本，补充微表情正负确认、矛盾类型和融合权重，形成 `EA-L4-Gold`。这样既不是简单下载公开数据，也不是盲目从零自采，而是面向我们当前 L4 模块的数据集二次开发。
